# ระบบลางานและขอสลับวัน WFH (Leave & WFH Day-Swap Management System)

ระบบบริหารจัดการวันลาและสลับวัน Work From Home (WFH) สไตล์ Modern SaaS Dashboard รองรับภาษาไทยสมบูรณ์แบบ ออกแบบตามหลัก Role-Based Access Control (RBAC) พร้อมระบบคำนวณสิทธิ์วันลาพักร้อนอัตโนมัติตามอายุงานและสูตร Pro-rate

---

## 🚀 จุดเด่นของระบบ (Key Features)

### 1. การจำลองสิทธิ์ผู้ใช้งาน (RBAC Simulation)
สลับมุมมองผู้ใช้ได้ทันทีจากเมนูด้านบน เพื่อทดสอบระบบได้ทั้ง 3 ระดับสิทธิ์:
- **พนักงานทั่วไป (Employee):**
  - ตัวอย่าง 1: `นายสมศักดิ์ สุขใจ` — พนักงาน Hybrid Group C (Year 0 Pro-rate สิทธิ์พักร้อน 3.0 วัน)
  - ตัวอย่าง 2: `นางสาวกานดา วิริยะ` — พนักงานต่างจังหวัด Remote 100% (Year 3 สิทธิ์พักร้อน 10 วัน)
  - ตัวอย่าง 3: `นางสาวพิชญา มณีวงศ์` — พนักงาน Hybrid Group A (มีคำขอลางานรอการอนุมัติ)
  - ตัวอย่าง 4: `นายณัฐพล เจริญผล` — พนักงาน Hybrid Group B (เงื่อนไขพิเศษบรรจุ 1 ม.ค. ได้สิทธิ์ Year 0 เต็ม 6.0 วัน)
  - ตัวอย่าง 5: `นายวิชาญ เด่นดี` — อยู่ระหว่างทดลองงาน (พักร้อน = 0 วัน ลาป่วย/กิจได้)
- **หัวหน้างาน / ผู้จัดการ (Manager / PM):**
  - `นายธนากร พัฒนเกียรติ` — Engineering Lead & PM
  - คิวพิจารณาคำขอรออนุมัติ (Pending Approvals) พร้อมเหตุผลและเอกสารแนบ คลิก `อนุมัติ` หรือ `ปฏิเสธ` พร้อมระบุความเห็น
  - ตารางเมทริกซ์ทีมประจำสัปดาห์ (Team Weekly Attendance Matrix) พร้อม **สรุปยอดคนเข้าออฟฟิศจริงแต่ละวัน (Daily Headcount)**
- **ฝ่ายบุคคล / ผู้ดูแลระบบ (HR / Super Admin):**
  - `นางสาวมณีรัตน์ ศรีสวัสดิ์` — HR Director & Super Admin
  - ทะเบียนข้อมูลพนักงาน (Employee Master Data) คำนวณวันลาพักร้อนอัตโนมัติตามสูตรบริษัท
  - แบบฟอร์มเพิ่ม/แก้ไขพนักงาน พร้อมระบบ **Live Vacation Calculation Preview** เมื่อเปลี่ยนวันเริ่มงานหรือวันผ่านโปร
  - รองรับการกำหนดโควตาพักร้อนด้วยตนเอง (Manual Quota Override)
  - บันทึกประวัติคำขอทั้งองค์กรและส่งออกไฟล์รายงาน CSV

## 📐 กฎเกณฑ์ทางธุรกิจ (Business Logic)

### 1. โควตาวันลามาตรฐาน (Standard Quotas)
- **ลาป่วย (Sick Leave):** 30 วันทำงาน / ปี
- **ลากิจ (Personal Leave):** 3 วันทำงาน / ปี
- **หน่วยการลา:** รองรับเต็มวัน (`1.0`), ครึ่งวันเช้า (`0.5`), และครึ่งวันบ่าย (`0.5`)

### 2. ลาพักร้อน (Vacation Leave) — Tenure & Pro-rate Rules
- รีเซ็ตทุกวันที่ 1 มกราคมของทุกปี
- **อยู่ระหว่างทดลองงาน (`isPassedProbation == false`):** 0 วัน (ยังไม่ได้รับสิทธิ์)
- **Year 0 (ปีปฏิทินที่ผ่านทดลองงาน):**
  - สูตร Pro-rate: `(12 - passMonth) * 0.5`
  - ตัวอย่าง: ผ่านโปรเดือน เม.ย. (4) = `(12 - 4) * 0.5 = 4.0 วัน`
  - ตัวอย่าง: ผ่านโปรเดือน มิ.ย. (6) = `(12 - 6) * 0.5 = 3.0 วัน`
  - **เงื่อนไขพิเศษ:** หากได้รับการบรรจุแต่งตั้งในวันที่ 1 มกราคม จะได้รับสิทธิ์ Year 0 = `6.0 วัน`
- **Year 1+ (นับจาก 1 ม.ค. ปีถัดไปหลังผ่านโปร `yearDiff = currentYear - passYear`):**
  - **Year 1** (`yearDiff == 1`): `6.0 วัน`
  - **Year 2 - 3** (`yearDiff == 2 หรือ 3`): `10.0 วัน`
  - **Year 4 - 5** (`yearDiff == 4 หรือ 5`): `15.0 วัน`
  - **Year 6+** (`yearDiff >= 6`): `20.0 วัน`

---

### 3. ระบบสลับวัน WFH เฉพาะกิจ (WFH Day-Swap Workflow)
สำหรับพนักงานกลุ่ม Hybrid (กรุงเทพฯ & ปริมณฑล):
- **วันที่ขอ WFH:** ต้องเป็นวันที่ตามตารางปกติเป็นวันเข้าออฟฟิศ
- **วันที่เข้าออฟฟิศชดเชย:** ต้องเป็นวันที่ตามตารางปกติเป็นวัน WFH และ**ต้องอยู่ภายในสัปดาห์เดียวกัน (จันทร์ - ศุกร์)**
- **ผลลัพธ์เมื่อได้รับอนุมัติ:**
  - **ไม่หักโควตาวันลาใดๆ**
  - ตารางประจำสัปดาห์และเมทริกซ์ทีมจะอัปเดตเป็น:
    - วันที่ขอ WFH: `🏠 WFH (สลับเฉพาะกิจ)`
    - วันที่เข้าชดเชย: `🏢 เข้าออฟฟิศ (ชดเชย)`

## 💻 Tech Stack
- **Frontend Framework:** React 19 + TypeScript
- **Styling:** Tailwind CSS + Google Prompt & Inter fonts
- **Icons:** Lucide React
- **Animations & Effects:** Canvas Confetti
- **Build Tool:** Vite 6

## 🛠️ วิธีการรันโปรเจกต์ (Getting Started)

```bash
# 1. ติดตั้ง Dependencies
npm install

# 2. เริ่มต้นเซิร์ฟเวอร์สำหรับพัฒนา (Development Server)
npm run dev

# 3. ตรวจสอบ Type และ Build สำหรับ Production
npm run build

# 4. ทดสอบพรีวิว Production Build
npm run preview
```
